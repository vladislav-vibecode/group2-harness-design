# 01 · Deck structure

A strong deck is built **before** it is designed. Each section opens with a divider, each
slide states one point, and each large section ends with a summary slide. A reader who only
reads dividers + titles + verdict bars should get the full story.

3. Recurring section recipes

## 1. Structure rules

1. **Context → problem → answer, per section.** Each section ends with what it means for
   the reader and what to do about it.
2. **Two altitudes.** In long decks keep the big picture (goals, direction, principles) and
   the concrete plan (steps, dates, owners) in separate sections; don't mix a multi-year
   ambition with a next-week task list on one slide.
3. **Answer the obvious objection on the next slide.** Claim → "but…" → honest sizing.
   Realistic ranges earn more trust than big promises.
4. **Question chains for complex logic.** When a conclusion rests on several decisions,
   announce them as numbered questions and give each its own slide with a breadcrumb
   «Вопрос #2» / "Question 2 of 4" top-right.
5. **Close every big section with a summary slide**: 2–3 grouped lists of numbered
   findings. This is the slide people screenshot.
6. **End with how it will work, who does it and next steps** — then a short closing slide,
   then an Appendix (details, full tables, method notes) in the same grammar.
7. **Effects as scenarios, not promises.** Show 2–3 scenarios with ranges and assumptions;
   mark the recommended one visually.

## 2. Deck shapes

### Short — 10–25 slides
Cover → context (1–3 slides) → one-page summary grid → divider → 6–10 argument slides →
plan / forecast table → team → next steps → closing.

### Medium — 30–60 slides
Cover → goals / task grid → section 1 (context: 4–8 slides + summary) → section 2
(analysis: 6–12 slides + summary) → section 3 (direction: 4–8 slides) → section 4 (plan:
6–12 slides, timeline, scenarios) → operating model → team → next steps → closing → Appendix.

### Long — 60–150 slides
Same as medium, plus:
- numbered blocks on dividers («Блок 1…N» / "Part 1…N");
- **repeating page pairs** for each item of a portfolio (overview grid + detail table),
  identical layout every time so the reader learns it once;
- a question chain inside the direction section;
- a results-over-time section (milestones by period, indicator history in small multiples,
  status matrix "done / not done / possible");
- one goal per slide pattern (hypothesis → mechanism → risks → expected effect).

## 3. Recurring section recipes

- **Track record**: left column of stat tiles (`00` periods, `0,0` score, pills) + right
  bar chart over time (last bar accent) + 3 numbered wins below.
- **Context block**: hero number + "what's happening / where's the tension / conclusion"
  (conclusion = inverted card).
- **Diagnosis block**: standard/checklist → main finding (big numbers) → summary Metric row →
  segment cards → drill-downs → effect of fixes.
- **Goal block**: Hypothesis → Mechanism → Risks → Expected effect (big `+00%`).
- **Team**: grouped role cards with initials and share of time; *no photos in templates*.
- **Ways of working**: 6 cards (cadence, statuses, reports, planning…).
- **Next steps**: 3–5 numbered rows + a START-type verdict.

## 4. Title formulas

| Pattern | Placeholder example |
|---|---|
| Claim + number | «Lorem ipsum: 00% dolor sit amet» |
| Contrast | «Lorem — ipsum, dolor — sit amet» |
| Change | «Lorem ipsum стало на 00% меньше» |
| Ratio | «Lorem ipsum differs 00× between A and B» |
| Recommendation | «Consectetur adipiscing: measure X, not Y» |
| Mechanism | «Lorem ipsum dolor fades fastest» |
| Plan | «Period 1–2: lorem ipsum and dolor in parallel» |
| Not-X-but-Y | «Lorem ipsum as a system, not a list of tasks» |
| Honest sizing | «Realistic: +0–0 in a period; more takes longer» |

Section tags (top-right) use `SECTION · SUBTOPIC` in caps: «LOREM · IPSUM». In a long deck
they double as navigation.
